# نظام متابعة تنفيذ المهام (Employee Task Follow-up)

سيستم مستقل (منفصل عن سيستم الـ SOP والكواليتي) لمتابعة تاسكات الموظفين ومواعيد مراجعتها،
مبني بنفس الستاك: Supabase + HTML/CSS/JS عادي + GitHub Pages.

## الفكرة

بتسجل تاسك لكل موظف فيه:
- اسم الموظف / الكود / الخط / المرحلة
- التاسك المطلوب
- اسم المشرف + ملاحظات
- معاد المراجعة: إما **معاد محدد** (مرة واحدة) أو **تكرار دوري** (كل X دقيقة/ساعة/يوم/أسبوع)

الداشبورد بيلوّن كل تاسك حسب قربه من الاستحقاق:
- 🟢 أخضر = في الموعد
- 🟡 أصفر = قربت تستحق
- 🔴 أحمر (نابض) = متأخرة

ولما التاسك يستحق، بييجي إشعار من المتصفح (Browser Notification) بالإضافة لظهوره في اللوحة.

## خطوات التشغيل

### 1. جهّز قاعدة البيانات
- ادخل على مشروع Supabase بتاعك (أو اعمل مشروع جديد لو عاوزه منفصل تماماً)
- روح SQL Editor وشغّل محتوى ملف `sql/schema.sql` كامل

### 2. اعمل حساب الأدمن
- من Supabase Dashboard -> Authentication -> Users -> Add user
- حط الإيميل والباسورد اللي هتدخل بيهم

### 3. اربط الإعدادات
- افتح `js/config.js`
- حط فيه:
  - `SUPABASE_URL` (من Project Settings -> API)
  - `SUPABASE_ANON_KEY` (من نفس الصفحة)

### 4. ارفعه على GitHub Pages
- اعمل ريبو جديد وارفع الملفات كلها
- من Settings -> Pages فعّل النشر من الفرع الرئيسي
- افتح الرابط اللي هيديهولك GitHub وسجل دخول

## ملاحظة عن الإشعارات

الإشعارات دي شغالة عن طريق Notification API في المتصفح، وبتحتاج:
- تدوس على "تفعيل الإشعارات" مرة واحدة وتسمح للمتصفح
- التاب/الصفحة تفضل مفتوحة (ولو في الخلفية) عشان تقدر تبعت التنبيه، لأن السيستم مستضاف على
  GitHub Pages (static) من غير سيرفر خلفي يقدر يبعت Push حتى لو التاب مقفول تماماً.
- لو عاوز موثوقية أعلى، الحل الأشمل هو ربط Push Notifications حقيقي (يحتاج سيرفر/Edge Function
  في Supabase) — ممكن نضيفه بعدين لو احتجته.
